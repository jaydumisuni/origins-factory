## Product identity lock

Origins Factory is:

> A model-optional, evidence-native mission operating environment that combines durable work ownership, full-stack engineering, cyber-physical control, independent verification, cross-machine continuity, and controlled capability synthesis.

Origins Factory is the portable workspace the owner opens to work with Hunter. It runs independently and is also the primary workspace inside the future custom OS.

Origins Factory is not:

- the custom OS;
- a VS Code/Cursor/Codex clone;
- an editor with an AI sidebar;
- a dashboard or launcher;
- a thin Tauri wrapper;
- a model router;
- a replacement for Hunter, AgentOps, CodeOps, Sergeant, Oracle, Lumi, X-Ray, Ptah, Software Builder, or specialist Gateways.

## Non-negotiable architecture

```text
Owner intent
→ Origins Factory
→ Hunter semantic understanding
→ AgentOps durable Mission/Operation graph
→ Capability Compiler
→ Rust/Python/specialist mechanical execution
→ Sergeant/X-Ray/deterministic assurance
→ Artifacts, handover, sanitation, recovery, and controlled learning
```

Three truths remain separate:

- **Semantic truth:** Hunter + AgentOps;
- **Mechanical truth:** Origins native runtime, specialist Gateways, Nodes, and later Ptah;
- **Assurance truth:** Sergeant, X-Ray, deterministic proof, and human acceptance.

Models amplify the system but cannot manufacture mechanical completion, specialist authority, or independent review.

## Runtime planes

Accepted language responsibilities:

- **React + TypeScript:** workspace UI and projections;
- **Rust:** persistent native control plane (`originsd`), PTYs, processes, filesystem/Git, Nodes, capabilities, IPC, events, recovery;
- **Python:** Hunter, AgentOps, CodeOps, provider/model integration, context compilation, capability selection, reconciliation, and upgrade proposals.

The UI must not own durable runtime truth. Exact desktop host, editor, terminal, docking, and IPC libraries remain implementation decisions until reviewed.
